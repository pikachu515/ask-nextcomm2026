# 0002. SafeLink를 ASK의 통신 모듈로 넣는다

| 항목 | 내용 |
|---|---|
| 상태 | 제안 (2026-11-14). SafeLink를 쓴 팀원의 확인이 필요하다 |
| 관련 쪽 | 4쪽, 6쪽, 8쪽, 10쪽 |
| 관련 문서 | [design/safelink.md](../design/safelink.md), [sim/safelink](../../sim/safelink/README.md) |

## 배경

팀원이 「ASK + SafeLink 기술보완 및 시뮬레이션 실행보고서」(2026-11-12)를 썼다. 긴급 정보가 제때, 쓸 수 있는 상태로 도착하게 하는 통신 관리 계층이다. 이 보고서는 처음 구성안을 바탕으로 썼기 때문에 [결정 0001](0001-combined-plan.md)의 내용은 반영돼 있지 않다.

두 안은 다루는 층이 다르다.

| | 결정 0001의 구조 | SafeLink |
|---|---|---|
| 다루는 것 | 누구에게 묻고, 여러 차량에 자원을 어떻게 나눌지 | 메시지 하나를 어떻게 제때 전달할지 |
| 강점 | 문제의 설득력, 사업화 | 통신 기술의 깊이, 실험의 엄밀함 |

## 결정

제안서의 뼈대(문제, 네 단계, 사업화)는 결정 0001을 따른다. SafeLink는 서비스 이름이 아니라 **ASK 안의 통신 모듈**로 6쪽에 넣는다.

| 가져오는 것 | 넣는 곳 |
|---|---|
| 응답 기한에서 차량 판단 시간, 제동 실행 시간, 안전 여유를 빼는 식 | 6쪽, [messages.md](../design/messages.md) |
| 관측 시각과 생성 시각의 구분, 도착 후 신선도 검사 | 4쪽, [messages.md](../design/messages.md) |
| 두 경로와 선택적 중복 | 6쪽 |
| 다섯 정책 비교와 예비 결과 | 6쪽, 10쪽 |
| 실험 원칙(공통 난수, 시드 100개, 불리한 결과 공개) | [sim/README.md](../../sim/README.md) |
| 한계 표와 단정하지 않는 문구 | [facts.md](../evidence/facts.md), [qa.md](../plain/qa.md) |

## 용어 통일

보고서, 코드, 제안서의 이름이 서로 달라서 제안서에서는 쉬운 말로 통일한다.

| 보고서 | 코드 | 제안서에서 쓰는 말 |
|---|---|---|
| P1 / P2 / P3 | tier 1 / 2 / 3 | 긴급 / 중요 / 일반 |
| L1 (NR-Uu) | A | 기지국을 거치는 경로 |
| L2 (NR-PC5) | B | 보조 경로 (직접통신 등) |
| Selective Packet Duplication | SAFE_LINK | 필요할 때만 두 경로로 보내기 |
| Age of Information | max_age | 정보 신선도 |

P1~P3이라는 이름은 제안서 쪽 번호(1쪽~10쪽)와 헷갈리므로 쓰지 않는다.

## 미룬 것

- SUMO 연동은 본선 준비로 미룬다. 접수 마감까지 시간이 부족하다.
- SafeLink를 제목이나 서비스명에 넣지 않는다. 이름이 둘이면 서비스가 흐려진다.

## 남은 질문

1. **작은 긴급 메시지는 항상 두 경로로 보내면 되지 않는가.** 모의실험에서 필요할 때만 두 경로로 보내는 방식은 항상 두 경로보다 전달률이 1.9%p 낮았다. 평소의 우연한 손실은 예측할 수 없기 때문이다. 긴급 메시지는 작아서 항상 두 번 보내도 부담이 적다. 선택적 중복의 이점은 관제 영상이나 센서 데이터처럼 큰 데이터에서 커진다. 적용 대상을 이렇게 나눌지 팀원과 정한다.
2. **보조 경로를 직접통신으로만 볼 것인가.** 5G 직접통신 장비는 보급이 적다. 다른 통신사 망을 보조 경로로 포함하면 약점이 줄어든다.
3. **장애 후 전환 기준의 타임아웃 값.** 지금 값(120ms)으로는 준비 시간이 80ms일 때 구조상 성공할 수 없다. 자세한 내용은 [코드 검토 메모](../design/safelink.md#코드-검토-메모)에 있다.
