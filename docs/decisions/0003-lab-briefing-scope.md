# 0003. 연구실 브리핑은 2단계의 센서 구성과 시연 장면에만 참고한다

| 항목 | 내용 |
|---|---|
| 상태 | 채택 (2026-11-16). 제안서의 표기 방식은 팀 확인이 필요하다 |
| 관련 쪽 | 5쪽, 10쪽 |
| 관련 문서 | [design/roadside-sensing.md](../design/roadside-sensing.md), [contest/rules.md](../contest/rules.md) |

## 배경

팀은 연구실에서 만든 「교차로 4D 레이다·라이다·RSU 활용안」 브리핑(2026-11-08)을 갖고 있다. 작성자는 대학원생이고, 내용이 겹쳐도 괜찮으며 가져다 써도 된다는 답을 받았다(2026-11-11 확인).

한편 대회 규정은 다음과 같다.

- 참가 대상에서 대학원생은 제외된다.
- 제출한 아이디어는 참가자가 직접 제안한 아이디어여야 한다.
- 타인의 아이디어를 무단으로 도용한 경우 심사와 수상이 취소될 수 있다.

허락을 받았으므로 무단 도용은 아니다. 다만 "직접 제안한 아이디어" 규정이 있으므로, 제안의 중심이 브리핑이어서는 안 된다.

## 결정

1. **핵심 아이디어는 팀의 것으로 둔다.** 막힌 무인차의 질문이라는 문제 정의, 네 단계 구조, 요청과 응답 방식, 통신 모듈은 팀이 만든 내용이다.
2. **브리핑은 2단계의 한 부분과 시연 계획에만 참고한다.** 범위는 아래 표와 같다.
3. **참고한 사실을 숨기지 않는다.** 제안서의 해당 쪽에 "교차로 센서 구성과 시연 계획은 OO 연구실의 설계를 참고함"처럼 한 줄로 밝힌다. 문구는 팀에서 정한다.
4. **브리핑 원본은 저장소에 올리지 않는다.** 요약은 [roadside-sensing.md](../design/roadside-sensing.md)에 둔다.

| 브리핑에서 참고하는 것 | 쓰는 곳 |
|---|---|
| 도로변 4D 레이다, 라이다, RSU, 엣지 PC의 역할 | 5쪽의 2단계 설명, 7쪽의 구성 |
| 구역 상태 세 가지(점유, 관측상 비어 있음, 확인 불가)와 차량 동작 | 5쪽 판단표 |
| 응답에 측정 시각과 유효기간을 붙이는 방식 | 4쪽 메시지 설명 |
| 시연 세 장면과 측정 지표 | 10쪽 본선 시연 계획 |

## 이유

- 규정 위반의 여지를 없앤다. 심사에서 "누구의 아이디어인가"를 물으면 팀의 기여와 참고한 부분을 나눠 답할 수 있다.
- 연구실 장비와 설계는 본선 시연에서 강점이 된다. 숨길 이유가 없다.

## 남은 질문

- 표기 문구와 넣을 위치를 팀에서 정한다. 연구실 이름을 적어도 되는지 작성자에게 확인한다.
- 본선에서 연구실 장비로 시연할 수 있는지 미리 확인한다.
