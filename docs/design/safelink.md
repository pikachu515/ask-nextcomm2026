# 통신 모듈 SafeLink

SafeLink는 ASK 안에서 긴급한 정보가 제때, 쓸 수 있는 상태로 도착하게 하는 부분이다. 팀원이 쓴 「ASK + SafeLink 기술보완 및 시뮬레이션 실행보고서」(2026-11-12)를 옮겨 정리하고, 코드를 실행해 확인한 내용을 덧붙였다. 서비스에 넣는 방식은 [결정 0002](../decisions/0002-safelink-as-comm-module.md)를 따른다.

## 풀려는 질문

같은 긴급 메시지를 보낼 때, 경로를 바꾸기만 하는 방식이나 항상 두 번 보내는 방식과 비교해 **제때 유효하게 도착하는 비율과 전송 비용의 균형**을 더 낫게 만들 수 있는가.

## 세 가지 축

섞어 쓰면 헷갈리는 세 가지 판단을 나눈다.

| 축 | 무엇을 판단하는가 | 해당하는 것 |
|---|---|---|
| 정보 확보 | 차량, 교차로, 주변 차량 가운데 누가 볼 수 있는가 | ASK의 네 단계 |
| 정보 가치 | 그 정보가 믿을 만하고 언제까지 쓸 수 있는가 | 출처, 신선도, 메시지 등급 |
| 통신 전달 | 지금 어느 경로로 보내는 것이 맞는가 | 기지국을 거치는 경로, 보조 경로, 둘 다 |

## 규칙의 순서

먼저 "이 정보가 맞는가, 언제까지 필요한가"를 정하고, 그다음 "어느 경로로 보낼 것인가"를 정한다.

| 순서 | 판단 항목 | 규칙 |
|---|---|---|
| 1. 필수 조건 | 출처, 관측 시각, 신뢰도 | 틀렸거나 만료된 정보는 경로와 상관없이 주행 판단에 쓰지 않는다 |
| 2. 메시지 등급 | 긴급, 중요, 일반 | 신호 변경, 보행자 접근, 정지선까지의 여유로 정한다 |
| 3. 경로 정책 | 경로별로 기한 안에 도착할 가능성, 전송 비용, 준비 시간 | 한 경로, 다른 경로, 두 경로 모두, 전송 불가 가운데 고른다 |
| 4. 받은 뒤 | 중복 제거, 기한, 신선도, 기록 | 조건에 못 미치면 차량에 "통신으로는 못 채웠다"고 알린다 |

메시지 항목과 신선도 검사는 [messages.md](messages.md)에 있다.

## 전송을 정하는 순서

1. 메시지의 출처, 관측 시각, 응답 기한을 확인한다. 이미 만료됐으면 쓰지 않는다.
2. 두 경로의 지금 손실률, 대기 지연, 준비 시간을 본다.
3. 한 경로만, 다른 경로만, 두 경로 모두 가운데 기한 안에 도착할 가능성이 목표를 넘는 후보를 추린다.
4. 그 가운데 전송 비용이 가장 작은 것을 고른다. 후보가 없으면 "기한 안에 전달하기 어렵다"고 차량에 알린다.
5. 받은 쪽은 중복을 버리고, 관측 시각으로 신선도를 확인한 뒤 기록한다.

첫 버전은 규칙으로 구현한다. 학습 모델은 같은 자리에 바꿔 끼울 수 있는 선택 사항이다. 언어 모델을 실시간 전송 결정에 넣지 않는다.

## 비교한 다섯 방식

| 코드 이름 | 제안서에서 쓰는 이름 | 동작 |
|---|---|---|
| `FIFO_A` | 온 순서대로 | 기지국 경로에서 먼저 온 메시지부터 보낸다 |
| `PRIO_EDF_A` | 급한 순서대로 | 긴급 등급을 먼저, 같은 등급이면 마감이 빠른 것부터 보낸다 |
| `REACTIVE` | 막히면 갈아타기 | 기지국 경로로 답이 안 오면 기다렸다가 보조 경로로 다시 보낸다 |
| `ALL_P1_DUP` | 항상 두 경로 | 긴급 메시지는 언제나 두 경로로 함께 보낸다 |
| `SAFE_LINK` | 필요할 때만 두 경로 | 통신 품질이 나쁘거나 기한이 촉박할 때만 두 경로로 보낸다 |

## 결과

시드 100개, 30초, 보조 경로 준비 시간 80ms. 모든 값은 가정에서 나온 모의실험 결과다(사실 카드 S-02).

| 방식 | 긴급 정보가 제때 유효하게 도착한 비율 | 평균 전송 횟수 | 추가 전송 |
|---|--:|--:|--:|
| 온 순서대로 | 53.94% | 1,617.1 | 0 |
| 급한 순서대로 | 92.14% | 1,617.1 | 0 |
| 막히면 갈아타기 | 92.14% | 1,658.9 | 41.8 |
| 항상 두 경로 | 98.14% | 2,053.5 | 436.4 |
| 필요할 때만 두 경로 | 96.23% | 1,725.2 | 108.0 |

읽는 법은 세 가지다.

- **급한 순서로 보내는 것만으로 54%에서 92%로 오른다.** 가장 큰 효과는 여기서 나온다.
- **두 경로를 쓰면 96~98%까지 오른다.** 항상 두 경로는 전송이 27% 늘고, 필요할 때만 두 경로는 7% 는다.
- **필요할 때만 두 경로는 항상 두 경로보다 1.9%p 낮다.** "더 안전하다"고 쓰면 안 된다. 전송을 적게 쓰면서 비슷한 전달률을 낸다고 써야 한다.

보조 경로의 준비 시간을 0ms로 두면 막히면 갈아타기가 98.18%로 가장 높다. 이 아이디어의 성능이 준비 시간에 크게 좌우된다는 뜻이며, 보고서도 이 반례를 그대로 밝혔다.

## 코드 검토 메모

2026-11-16에 코드를 읽고 실행해 확인한 내용이다. 코드는 [sim/safelink](../../sim/safelink/README.md)에 있다.

**확인된 것**

- 보고서 표의 수치가 그대로 재현된다.
- 메시지마다 난수를 미리 뽑아 두고 모든 방식에 똑같이 쓴다. 방식 사이의 차이는 선택에서만 생긴다.
- 표준 라이브러리만 쓰고, 결과 파일을 쓰는 것 말고는 다른 동작이 없다.

**고친 것**

- 압축 파일의 이름은 `safelink_demo.py`인데 평가 코드는 `ASK_SafeLink_demo`를 불러와서 실행되지 않았다. 불러오는 이름을 맞췄다.
- 결과 파일이 `results` 폴더에 저장되도록 두 줄을 바꿨다.

**결과를 해석할 때 알아 둘 것**

| 관찰 | 뜻 |
|---|---|
| 막히면 갈아타기는 120ms를 기다린 뒤 준비 80ms, 보조 경로 지연 30~58ms가 더해진다. 합이 230ms를 넘는데 긴급 정보의 허용 나이가 230ms다 | 준비 시간이 80ms일 때는 구조상 성공할 수 없다. 급한 순서대로와 값이 같은 이유다. 기다리는 시간(120ms)도 함께 바꿔 봐야 공정한 비교가 된다 |
| 평소에도 기지국 경로에서 2.5%가 우연히 손실된다. 이 손실은 미리 알 수 없다 | 필요할 때만 두 경로로 보내는 방식은 이 손실을 막지 못한다. 항상 두 경로보다 낮게 나오는 이유다 |
| 보조 경로에는 용량 제한이 없다 | 항상 두 경로로 보내는 비용이 전송 횟수로만 잡힌다. 실제로는 여러 차량이 모두 두 번 보내면 보조 경로가 붐빌 수 있는데, 그 효과는 들어 있지 않다 |
| 품질이 나쁜지의 판단에 현재 신호 품질과 혼잡 구간의 시각을 그대로 쓴다 | 학습된 예측이 아니다. "AI가 장애를 예측한다"고 쓰면 안 된다 |
| 허용 나이를 요청을 보낸 시각부터 잰다 | 관측 시각과 생성 시각의 차이는 아직 모델에 없다 |
| `simulate()` 안의 `rng`와 `math` 불러오기는 쓰이지 않는다 | 동작에는 영향이 없다. 정리해도 된다 |

**장애 시나리오의 구현 범위**

보고서는 시나리오 일곱 개(S0~S6)를 제시했다. 지금 코드는 한 번의 30초 안에 혼잡(13~18초), 품질 악화(12~13초), 두 경로 동시 장애(21~22.5초)를 차례로 넣은 한 가지 환경이다. 예측 실패(S3), 전달 후 만료(S5), 잘못된 경보(S6)는 따로 구현돼 있지 않다.

## 한계

- 통신 물리 계층, 재전송, 전파 환경을 구현하지 않았다. 보조 경로는 "직접통신처럼 동작하는 가상의 경로"다.
- 수치는 실제 5G·6G 측정값이 아니다.
- 메시지가 잘 도착하는 것과 차량이 안전하게 달리는 것은 다르다. 차량 거동은 이 모의실험에 없다.
- 통신사는 외부 서비스에 기지국의 자원 배분 권한을 주지 않는다. 초기 제품은 단말과 응용 계층에서 경로를 고르는 수준이고, 기지국 연동은 통신사와 협력해야 하는 범위다.
- 5G 직접통신 장비는 보급이 적다. 장비가 있는 시범 구역을 초기 시장으로 본다.

## 다음에 할 일

보고서가 제시한 개선 가설과, 검토하면서 나온 질문을 합쳤다.

- [ ] 작은 긴급 메시지는 항상 두 경로로 보내고, 선택적 중복은 큰 데이터에 적용할지 정한다 ([결정 0002](../decisions/0002-safelink-as-comm-module.md)의 남은 질문)
- [ ] 보조 경로만 쓰는 선택지를 긴급 메시지에도 넣는다
- [ ] 막히면 갈아타기의 기다리는 시간을 여러 값으로 돌려 본다
- [ ] 보조 경로에 용량 제한을 넣어 항상 두 경로의 부담을 본다
- [ ] 본선 준비 단계에서 SUMO와 연동해 차량 거동(정지선 침범, 감속 시작 거리)을 본다
