# 사실 카드

제안서와 발표에 쓰는 수치와 주장은 이 문서에 있는 것만 쓴다. 새로 쓰고 싶은 사실이 있으면 여기에 먼저 추가한다.

## 확인 상태 읽는 법

| 표시 | 뜻 | 제안서에 쓸 때 |
|---|---|---|
| 원문 확인 | 해당 회사나 기관의 원문을 열어 확인했다 | 그대로 써도 된다 |
| 기사 확인 | 보도 기사나 2차 자료를 열어 확인했다 | 써도 되지만 "보도에 따르면"을 붙인다 |
| 요약만 확인 | 검색 결과 요약으로만 봤다 | **원문을 열어 확인한 뒤** 쓴다 |
| 팀 출처 | 팀 구성안에 실린 출처다. 링크가 이 저장소에 없다 | 담당자가 링크를 채우고 원문을 확인한 뒤 쓴다 |
| 자체 계산 | 우리가 계산한 값이다 | 가정을 함께 적는다 |
| 모의실험 | 가정값으로 돌린 결과다 | "가정값 기준"을 붙인다 |

확인 날짜가 적힌 항목은 그날 열어 본 것이다.

## E. 자체 계산과 모의실험

| 번호 | 내용 | 근거 | 상태 |
|---|---|---|---|
| C-01 | 시속 50km, 감속도 2m/s²로 부드럽게 멈추려면 약 48m가 필요하다. 정지선 100m 전에 물으면 약 3.7초, 60m 전에 물으면 약 0.85초 안에 답이 와야 한다. 차량의 판단·제동 시간과 안전 여유를 빼면 실제 기한은 더 짧다 | [messages.md](../design/messages.md#응답-기한) | 자체 계산 |
| S-01 | 요청 폭주 모의실험. 차량 200대, 관제사 5명, 요청이 10배로 느는 30분. 차로를 막은 시간(차량·분)은 사람만 2,853, 교차로 응답 추가 1,777(38% 감소), 통신 보장 추가 919(68% 감소), 우선 배정과 대피 추가 216(92% 감소). 동시에 멈춘 차량은 최대 146대에서 59대로 준다 | [sim/surge](../../sim/surge/README.md), 시드 100개 | 모의실험 (11.16) |
| S-02 | 긴급 정보 전달률 모의실험. 긴급 정보가 제때, 쓸 수 있는 상태로 도착한 비율은 온 순서대로 53.9%, 급한 순서대로 92.1%, 필요할 때만 두 경로(SafeLink) 96.2%, 항상 두 경로 98.1%. 추가 전송은 SafeLink가 7%, 항상 두 경로가 27%다 | [sim/safelink](../../sim/safelink/README.md), 시드 100개 | 모의실험 (11.16) |

**S-01을 쓸 때.** 마지막 단계(92%)는 "기한을 넘긴 차량의 70%가 갓길로 비킬 수 있다"는 가정에 크게 좌우된다. 대표 수치는 대피를 뺀 68%를 쓴다. 우선 배정을 하면 차로를 막지 않은 차량의 대기가 길어진다는 점(95% 해결 시간 708초에서 1,067초)도 숨기지 않는다.

**S-02를 쓸 때.** 필요할 때만 두 경로로 보내는 방식은 항상 두 경로보다 전달률이 1.9%p 낮다. "더 안전하다"가 아니라 "전송을 적게 쓰면서 비슷한 전달률을 낸다"로 쓴다. 보조 경로의 준비 시간이 0이면 단순 전환 방식이 98.2%로 더 높게 나온다.

## 쓰지 않는 표현

| 쓰지 않는다 | 이유 | 대신 |
|---|---|---|
| 사고를 몇 % 줄인다 | 사고율을 검증한 적이 없다 | 도로를 막고 선 시간을 줄인다 (모의실험, 가정값 기준) |
| 판단 시한을 보장한다 | 보장할 수 없다 | 급한 요청부터 보내 제때 도착하는 비율을 높인다 |
| 기존에는 이런 방식이 없다 | C-ITS에도 사각지대 경고가 있고, 소프트뱅크의 실증도 있다 | 요청이 몰리는 순간에 통신, AI, 사람을 함께 나눠 쓰는 점이 다르다 |
| 급정거 없이 무중단 주행 | 답이 없으면 멈추는 것이 원칙이다 | 불확실하면 미리 감속하고 정지선 앞에 선다 |
