# 참가신청서

주최 측 양식은 [`refs/official/01_참가신청서_양식.hwp`](../../refs/official)에 있다. 한 쪽짜리 서식이고, 아이디어를 길게 쓰는 칸은 없다. 아이디어 설명은 모두 [제안서](../proposal/README.md)에 들어간다.

> [!IMPORTANT]
> 이름, 연락처, 이메일이 들어가므로 **작성한 신청서는 저장소에 올리지 않는다.** 양식을 복사해 각자 컴퓨터에서 채운다.

## 양식에 있는 칸

| 구역 | 칸 | 채우는 사람 | 메모 |
|---|---|---|---|
| 1. 참가 형태 | 개인 참가 / 팀 참가 | 대표자 | **팀 참가**에 표시 |
| 2. 참가자(팀) 정보 | 팀명 | 팀 | 제안서 파일명과 같아야 한다 |
| | 아이디어명 | 팀 | 제안서 파일명과 같아야 한다 |
| | 대표자 이름, 소속대학, 학과(전공), 학년, 휴대폰, 이메일 | 대표자 | 연락처와 이메일은 대표자만 적는다 |
| 3. 팀원 정보 | 팀장과 팀원의 성명, 소속대학, 학과(전공), 학년, **역할** | 각자 | 팀원 칸이 세 줄이다. 우리는 팀장 1, 팀원 2 |
| | 개인정보 수집·이용 동의 | 각자 | 세 명 모두 표시 |
| 확인 | 날짜, 대표자 성명과 서명 | 대표자 | 서명 방식은 구글폼 안내를 따른다 |

## 정해야 할 것

### 팀명

파일명이 `팀명_아이디어명`이므로 짧은 이름이 좋다. 팀에서 정한다.

### 아이디어명

신청서와 제안서 표지, 파일명에 똑같이 쓴다. 한 번 들으면 무엇을 하는지 알 수 있어야 한다.

| 후보 | 특징 |
|---|---|
| 막히면 ASK: 길에서 막힌 무인차에게 교차로가 먼저 답하는 통신 서비스 | 무엇을 하는지 가장 잘 드러난다. 길다 |
| ASK, 막힌 무인차에 교차로가 먼저 답한다 | 저장소 대문과 같은 문구 |
| 교차로가 먼저 답하는 무인차 통신 서비스 ASK | 서비스 종류가 먼저 나온다 |

파일명에는 줄인 이름을 써도 된다. 예: `팀명_막히면ASK.pdf`. 다만 신청서의 아이디어명과 같은 말이 들어가게 한다.

### 역할 칸에 쓸 말

칸이 좁으니 한 줄로 쓴다. [역할 분담(안)](../team/roles.md)에 맞춘 문구다.

| 구분 | 역할 칸에 쓸 말 |
|---|---|
| 팀장(대표자) | 총괄, 문제 정의와 사업화 |
| 팀원 | 통신 설계와 모의실험 |
| 팀원 | 서비스 구조와 센싱·시연 설계 |

## 서명하기 전에 읽을 것

신청서 아래에는 대표자가 확인하는 문구가 있다.

- 참가 자격과 운영 사항을 확인했고, 적은 내용이 사실이다.
- 아이디어가 남의 아이디어를 무단으로 가져왔거나 다른 공모전에서 상을 받은 작품이면 심사와 수상이 취소될 수 있다.

우리 팀이 미리 확인할 것은 세 가지다.

- [ ] 세 명 모두 **재학생**이다. 휴학생과 대학원생은 참가할 수 없다
- [ ] 이 아이디어를 다른 공모전에 내서 상을 받은 적이 없다
- [ ] 연구실 설계를 참고한 범위와 표기 방식을 정했다 ([결정 0003](../decisions/0003-lab-briefing-scope.md))

## 내는 방법

- 제안서와 함께 구글폼으로 낸다. 구글폼 주소는 포스터의 QR에 있다.
- HWP 그대로 내는지 PDF로 바꿔 내는지는 구글폼 안내를 보고 정한다. 아직 확인하지 못했다.
- 상금은 3인 이상 팀의 경우 팀장 40%, 나머지를 균등하게 나누는 것이 주최 측 원칙이다. 누가 대표자를 맡을지 정할 때 알아 둔다.
- 낸 뒤의 점검은 [제출 체크리스트](../contest/submission-checklist.md)로 한다.
